# #136 Complete Series — Phase 0 audit

Status: historical Phase 0 audit. Stephanie approved the two-stage flow, Hardcover-first waterfall, lazy loading, manual corrections, and contextual Series detail. Local implementation and migration notes are in [SERIES_DISCOVERY_136](SERIES_DISCOVERY_136.md). Audited against `origin/main` at `6f4ac7a`, which includes #135.

## Product and cohesion check

One reusable Series detail should serve Book detail, Books series search, and the existing contextual Collections deep link. A canonical `whimsy_books` row continues to own each added book, its selected edition, status, reviews, reads, journal and sessions. A ghost is a catalog reference attached to that series; opening or starring it never creates a Library book. Adding an edition creates or reuses one canonical book, then links that ID to the existing series. Saved names remain snapshots where history needs them; metadata refresh cannot rewrite past reads or user corrections. Other media series and manual book series continue to work.

## Current implementation

- `collection_series` is an owner-scoped series record; `collection_series_members` references exactly one saved book or media item and stores decimal `sequence`, role and release state. Its current progress denominator is only the manually linked, released mainline members. #135 book detail links to `/collections?view=series&series=<id>`.
- `SeriesLibrary` renders only saved members. “Create new book” embeds the full Bookshelf editor; “Connect existing” links a saved item. There is no catalog discovery, ghost, or inline edition add.
- Book search uses server-side Google Books volume search and Open Library work/edition search. `BookCandidate` already carries Google volume ID, Open Library work/edition IDs, ISBN, covers and edition metadata. A saved book retains one `metadataSource`; manually entered books may have no external ID. The current edition strip is inside `BookSearch` and fills the full Add Book form; it is not a reusable quick-add sheet.
- Search-result deduplication uses ISBN-13 or normalized title/first author; it does **not** guard against a duplicate saved Library book. `sameEdition` compares Open Library edition key or ISBN-13. Quick add needs a cross-provider work/edition match and an explicit “already in your Library” outcome before writing.
- `collection_media_items.favorite` is for media. `canonicalItems` sets book `favorite:false`; there is no persistent book/ghost wishlist. A separate owner-scoped star state is needed, without creating a book.

**Answer to the total question:** Muse can populate a *known installment count* from a provider catalog, then show missing installments as ghosts. Google Books alone cannot reliably supply that count for ordinary novels with the current API key. “Known” must stay visible: a provider may omit forthcoming or obscure books, and editions/omnibus volumes must not inflate the work count.

**Smallest viable multi-source resolver:** Start with Muse's saved series, reader corrections and a fresh cache. Use the Library book's stored Open Library work ID where present; otherwise resolve a stored ISBN to an Open Library work once, or use title/author only as a candidate requiring confirmation. If no usable ordered catalog is cached, try Hardcover only when its scoped credential is configured; otherwise or on a weak/no match, try Wikidata through the confirmed Open Library work ID. Use an Open Library `series:` subject query for a final membership-only fallback. Choose one confident ordered base catalog per series; merge extra entries from another source only when work identity and order can be reconciled, never by a title/count guess. Unnumbered Open Library entries remain “order unknown” until corrected. Cache the result per series; an explicit Refresh rechecks sources. This yields automatic discovery without a global import or per-ghost fetches.

## Proposed integrated data flow

### Stage 1 — lightweight series discovery

1. From book detail or Series, resolve/select the **same** owner-scoped `collection_series` record. For a book without a series, offer discovery candidates; never auto-attach an ambiguous match.
2. On opening or explicit refresh, run the bounded resolver above for this series only: source series ID/name and installment work IDs, titles, positions, and authors only if already included. At most a few identity/series calls are allowed, with no per-installment fanout. Do not fetch editions, covers, descriptions or page counts, create `whimsy_books` rows, or fetch anything for unrelated series.
3. Keep only a small owner-scoped catalog relationship for that series: source/work IDs, title/author snapshots, decimal position and display label, source provenance, user corrections and independent star state. Role/release state is recorded only when actually known or manually set. This is neither a global book catalog nor a second Library. Existing `collection_series_members` still references saved books; a matching catalog entry points to that membership/book rather than copying its edition or reading data.
4. Match catalog works against existing Library books by stable work/source identifiers, then ISBN where known, then conservative title/author review for legacy manual books. Never turn a possible title match into an automatic duplicate or link. Refresh merges source changes without overwriting manual corrections or removing an entry just because a provider omitted it. Readers can add a missing catalog entry or correct its order/role themselves.
5. Render owned books and lightweight ghost entries together in the existing Series view. A ghost says **“Not on your shelf”** and shows its position, title, author if known and Add (plus the issue's star action). No edition details or full book record are fetched for ghosts. Counts distinguish **known mainline works**, **in Library**, **distinct completed**, **currently reading** and **remaining**; label the catalog “known so far” when completeness is uncertain. Rereads do not add another distinct completion.

### Stage 2 — enrich only the selected ghost

6. Tapping Add first checks for an already owned match and offers **Connect existing** when appropriate. Otherwise it opens an in-place mobile sheet or desktop modal and calls the existing authenticated `/api/books/search` with the ghost's title and author prefilled. Google Books remains primary for edition candidates; Open Library remains the existing fallback and detailed work-edition source through `/api/books/editions`. This distinction matters: Muse's current edition route is Open Library-backed, while Google provides volume-level edition candidates through search. Only this selected installment incurs those calls. Show available format, publisher/year, language, pages and cover when supplied, with manual entry if search fails.
7. Choosing one edition checks Library work/ISBN/metadata IDs again, then saves or reuses **one** canonical `whimsy_books` row and links it to the existing series/catalog entry. Update the current series view immediately from Muse's book and collection stores so that the ghost becomes the owned row without navigation or reload. A partial book-save/link failure must be recoverable without a second book. Existing readings, sessions, reviews, ratings, editions and series links are untouched.
8. A ghost's star persists independently of adding it. After add, decide whether the star remains an interest marker or becomes a book-level favorite, but never turn it into a second book. Account export/delete and RLS must include any new owner data.

## Experience direction

Use the #135 cover atmosphere and editorial typography for a series hero, with a compact spine/cover procession and honest “known so far” progress. Desktop shows the ordered collection and a calm contextual edition panel; mobile uses a full-width sequence and a safe-area-aware edition sheet. Ghosts use a light outline/spine treatment without a cover fetch and say “Not on your shelf”; saved books show their existing covers, status, last-read context and detail link. Add/star actions remain reachable without scrolling back or navigating away. User-corrected order/role is visible and editable. Existing Muse themes, materials, focus states and reduced-motion rules govern both layouts; the screenshot is flow inspiration, not a visual template.

## Gates and risks before implementation

- Verify Hardcover catalog coverage and position accuracy when a read-only scoped credential is available. Wikidata already supplies a keyless ordered fallback for the tested ACOTAR work; Open Library supplies membership-only fallback. Include missing/ongoing/novella samples before claiming broad coverage. No single source's count proves completeness.
- Confirm the persisted catalog/star schema and migration path; run staging first. Existing series/member IDs and book histories must remain unchanged.
- Test cross-provider matching, duplicate prevention, same-screen add/link, retry after partial failure, stars, corrections surviving refresh, and all series-count distinctions. Check desktop/mobile and every theme.
- Review provider attribution, caching TTL/invalidation and rate limits. Keep discovery to bounded series/identity requests with no per-ghost fanout; load only the selected installment's editions and covers after Add.

**Approved direction:** local-first, bounded Hardcover → Wikidata → Open Library resolution; Google Books remains the on-demand edition path. The implementation is local only. Hosted migration and deployment still require separate approval.
